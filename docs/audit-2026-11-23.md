# Audit and hardening, 23 Nov 2026

A full pass over the live site (https://nepse-analyzer-peach.vercel.app), the code, the Supabase
project and the Vercel settings: navigation and state, data accuracy and freshness, layout
stability, and security. Every finding below was reproduced on the live site or in a production
build before it was fixed, and every fix has a test.

## Findings and fixes

### High

| # | Finding | Evidence | Fix |
|---|---|---|---|
| H1 | **The NEPSE Index showed 0.00% (0.00) for the day.** After the close NEPSE's `getNepseIndex` reports `previousClose` equal to the close for the four main indices. | Live Market page, 23 Nov: 2,623.56, 0.00%. Friday 20 Nov closed at 2,621.29 (Khabarhub, nepsetrading.com), so the change was **+2.27 (+0.09%)**. Sensitive, Float and Sensitive Float also showed ~0.00%. | Every index's previous close is our own final close of the previous trading day (the last `market_daily` day before), on the website (`lib/indices.ts`) and in the live and end-of-day jobs before writing `index_daily` (`settle_index_prev_close` in `scripts/ingest/common.py`). NEPSE's field is used only when nothing is stored. A first fix that only replaced an identical value left Sensitive (-0.00%) and Float (-0.01%) a rounding step off; verified on the live site. |
| H2 | **Sell and Hold calls showed a buy plan.** The company page showed "Buy zone" and "Target 1/2" (e.g. CKHL, a Sell: buy zone 390–405, Target 1 +28.4%), contradicting the call. | Live `/c/CKHL`. | The buy plan (buy zone, targets) appears on buy calls only. Hold and sell calls show "Exit if it falls below", support and resistance, with a one-line explanation; the chart draws only the exit line. Guide updated. |
| H3 | **Signals filters and sort were lost on Back, refresh and links.** Filter by Sell + Hydro Power + search + sort, open a company, press Back: everything reset to defaults. | Reproduced live. | Filters live in the address (`?call=sell&sector=…&q=…&sort=…`), written with `replaceState` (no extra Back steps), read on mount and on `popstate`, validated (`lib/signals.ts`). "Clear filters" and a row count added. |
| H4 | **Scrolling Signals downloaded every company page in the background.** Each visible row's link was prefetched (≈148 KB RSC each, ≈40 MB for 269 rows), each a server render with ~9 database reads when not cached, and again after every auto-refresh. | Live network log: 15 `/c/…` requests after two screens of scrolling. | `prefetch={false}` on company links (tables, lists, search). A root `loading.tsx` skeleton gives instant feedback on click instead. |

### Medium

| # | Finding | Fix |
|---|---|---|
| M1 | Header "Market closed · 36 min ago" came from the newest heartbeat of any job, here the Supabase **timer** (16:09), while prices were from 15:35. | The stamp uses only data jobs (live, end of day, analytics) that succeeded (`DATA_JOBS` in `lib/market.ts`). |
| M2 | A starred company that did not trade on the latest day silently disappeared from "Your stocks" (e.g. NLO). | Rows come from prices and calls; such a company shows its last close labelled "close of <day>". |
| M3 | Ranges race: the analytics job wrote calls first, then ranges in two batches. A page read in between cached "No ranges" (with a wrong explanation) for 10 minutes. | Ranges are written first and calls last, in one request (`daily_analytics.py`). The page no longer blames illiquidity when a usable call has no range yet. |
| M4 | Paged reads without a unique `order` (Postgres does not promise a stable order between pages): the Track record's live coverage (>1,000 scored rows), and in the analytics job the per-company backtest lookup (~3,500 rows) that sets "Reliable in backtest" and confidence. | Every paged read orders by a unique key, in the website and the jobs. The mock database shuffles unordered reads to catch regressions. |
| M5 | "Your stocks" chip looked like a call tab but combined with it; its count and the call counts ignored the other filters, so badges did not match the table. | Separate "Only your stocks" toggle; every count is the number of rows that chip would show (`chipCounts`). |
| M6 | Chart rebuilt on every range click and every minute's refresh, flickering and losing the reader's zoom; "Today" view could stick on an empty chart after a new day started. | Chart rebuilt only when the numbers change (content keys); range buttons move the view of the existing chart; light/dark switch handled; empty "Today" falls back to daily. |
| M7 | Any `/c/<anything>` reached the database and created a cached page; `/c/nabil` was a second copy of `/c/NABIL`. | Symbol checked before any read (`lib/symbol.ts`), 404 otherwise; lower case redirects to the canonical page. |
| M8 | No Content-Security-Policy, Permissions-Policy or COOP. | Added in `next.config.ts` (CSP locks scripts, connections, frames and forms to the site; `'unsafe-inline'` remains because cached ISR pages cannot carry nonces). |
| M9 | Feedback form: a lost connection threw to the error page and lost the message; React's form reset could clear text after an error; a quick double tap could send twice; one script could use up the database's 20-an-hour limit for everyone. | Sent through a transition with a single-send guard; failures show on the form with the text kept; per-visitor soft limit (5 per 10 minutes) in front of the database limit. |
| M10 | Data health showed a stopped job as "ok" (the watchdog, hourly on trading afternoons, last reported 5 h earlier). No warning when a final close had no calls. | Jobs past their rhythm show "late" with the reason; a missing day of calls after 16:30 raises a banner. |

## Checks with nothing to fix

* **Supabase (read-only queries in the SQL editor, 23 Nov):** 19 tables in `public`, row level security on every one; the public role has no table-level write anywhere; the only write is `INSERT` of `kind, page, message, name` on `feedback`, matching the only write policy; the `latest_job_runs` view uses `security_invoker=true`; no function in `public` is executable by the public role; `timer` schema and Vault are closed to it; no tables in the realtime publication (the site does not use realtime). The public role can execute `net.http_*` (pg_net's Supabase default, owned by `supabase_admin`), but `net` is not an API schema and the key never reaches browsers; noted, not changed.
* **Vercel:** environment variables are `SUPABASE_URL` and `SUPABASE_ANON_KEY` only, both server-side (no `NEXT_PUBLIC_`), no service key. The site refuses a service key (`keyProblem`). Note: the key is set for Production only, so preview deployments show the "Almost ready" screen.
* **XSS / injection:** no `dangerouslySetInnerHTML`, `eval` or `innerHTML`; React escapes all text; database values are sent as encoded query parameters, never SQL; the feedback `?about=` value is shown as text (tested with an `<img onerror>` payload).
* **Dependencies:** `npm audit`: 0 vulnerabilities. Python: `flask 3.1.0` (two advisories) comes pinned by the NEPSE library and is never run as a server by the jobs; left as is.
* **GitHub Actions:** inputs reach scripts through `env`, not inline expressions; permissions are read-only except the feedback issue job.
